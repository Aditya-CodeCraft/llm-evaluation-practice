# C++ audits of AI-generated code

Each folder holds one piece of C++ generated by an AI coding assistant for a short prompt, audited for one class of memory or concurrency bug. Every bug is **reproduced under a sanitizer**, and the write-up gives the root cause, the fix, and a verdict.

| # | Bug class | Sanitizer | What the plain build did | Verdict | Write-up |
|---|---|---|---|---|---|
| 01 | Out-of-bounds write (prefix-sum array one element too small) | ASan | passed its test silently | Reject | [`01-prefix-sum-out-of-bounds`](01-prefix-sum-out-of-bounds/README.md) |
| 02 | Memory leak on the error path (plus accepts `"4,,15"` and overflowing values) | ASan / LeakSanitizer | passed its test silently | Reject | [`02-parse-numbers-leak`](02-parse-numbers-leak/README.md) |
| 03 | Data race on a shared accumulator | TSan | wrong, different total every run | Reject | [`03-parallel-sum-data-race`](03-parallel-sum-data-race/README.md) |
| 04 | Undefined behavior: signed overflow in `(lo + hi) / 2` | UBSan | infinite loop | Reject | [`04-binary-search-overflow`](04-binary-search-overflow/README.md) |

Two of the four bugs pass ordinary tests, which is the main point of the exercise: a sanitizer turns silent memory corruption into a report with a file and line.

## Layout of each folder

- `buggy.cpp`: the generated function, verbatim, plus a small `main()` test driver.
- `fixed.cpp`: the corrected version with the same driver (some fixes add edge-case checks).
- `SANITIZER`: the `-fsanitize=` value that reproduces the bug.
- `README.md`: the prompt, the sanitizer output, how to read it, the root cause, an issue table, the fix, and a verdict.

## Re-run everything

```sh
sh cpp-audits/run.sh clang++   # or g++
```

The script compiles each `buggy.cpp` and `fixed.cpp` with `-g -O1 -fsanitize=<SANITIZER>`. It checks that the buggy build **produces** a sanitizer report and that the fixed build runs **clean** with its self-checks passing. It exits non-zero otherwise. The [`C++ audits`](../.github/workflows/cpp-audits.yml) GitHub Actions workflow runs it with GCC and Clang on every push.

Requirements: Linux with GCC or Clang (`libclang-rt-<ver>-dev` for Clang's sanitizers). If TSan aborts with `unexpected memory mapping`, run `sudo sysctl vm.mmap_rnd_bits=28` or `setarch -R sh cpp-audits/run.sh`.

The sanitizer excerpts in the write-ups come from GCC 13 / libstdc++ on Ubuntu 24.04, with paths shortened. Clang reports the same errors at the same lines.
